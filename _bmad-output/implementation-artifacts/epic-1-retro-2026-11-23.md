# Epic 1 retrospective

Epic 1 passed. All eight stories (1.1 to 1.8) are finished, CI passed, and the live site works. A few follow-ups remain. None of them should hold up Epic 2.

## What this review covered

I looked at the 16 commits from `1dab4a7` (Story 1.1) to `8d8f99e`, the eight story specs, the epic plan in `epics.md`, the architecture and design documents, the list of postponed work in `deferred-work.md`, and the sprint tracking file.

Some things were not covered. This is the first retrospective, so there was no earlier one to compare against. I did not read the chat logs for Stories 1.1 to 1.5, only their specs. I did the review myself in one session, without separate reviewer agents. There was no team discussion.

## What went well

- The code follows the project's rules about which parts may use which. The web app only uses the two packages it is allowed to use. When I added a forbidden import on purpose, the lint check caught it (rules in `.oxlintrc.json`).
- No logic is copied in two places. The pipeline and the web app both check the data files, but they use the same shared checks, which is the intended design.
- No file has grown too big. The largest source file is about 140 lines. The one to watch is `apps/web/src/WatchScreen.tsx`, because Epic 2 adds more to it.
- Every test the epic plan asked for exists: one per ad rule, the order of the reasons, the timing edge cases (`packages/policy/src/pause.test.ts`, lines 57 to 61) and the prompt-injection scene.
- Every acceptance criterion in `epics.md` is backed by code plus a test or a browser check.

## What needs fixing

1. **The planning documents no longer match the code in three places.**
   - The architecture doc (`ARCHITECTURE-SPINE.md`, line 134) and `epics.md` (line 260) describe `resolvePause` with a third input called `session`. The code (`packages/policy/src/pause.ts`) takes two inputs, because you decided in Story 1.4 to leave `session` out until a story needs it.
   - `DESIGN.md` (line 118) says the fonts load from Google Fonts. The architecture says the site must host its own fonts, and that is what it now does (`apps/web/src/index.css`, line 2).
   - The architecture doc's list of tools and versions does not include the two font packages added in Story 1.6 (`@fontsource/lora` and `@fontsource/raleway`, version 5.3.0). The tool list in `epic-1-context.md` is also out of date.

2. **Nothing checks that video and image files exist.** `pnpm decide --check` makes sure every product the site needs has a product file. It does not check that the clip's video file or the product's image file is really there. If one went missing, the site would show it broken. This matters more in Epic 4, when all the real videos and images arrive.

3. **Nothing tests the pause screen automatically.** The code that reacts to pausing, seeking, pressing Escape and reaching the end of the clip (`WatchScreen.tsx`) has no automated test. Its one real bug, the overlay opening before you had paused, was caught only because I tested in the browser by hand. Epic 2 adds more code to the same screen before the planned browser test in Story 5.5.

4. **Stories 1.6 to 1.8 had a lighter review.** You asked me not to check in, so I approved my own specs and reviewed my own work in the same session, without separate reviewer agents. Story 1.5's separate review found 16 problems, two of them medium. My reviews of 1.6, 1.7 and 1.8 found 3, 3 and 6. Some of that difference is likely the weaker review, not cleaner code.

5. **Smaller items, already tracked in `deferred-work.md`:**
   - I tested only in Chrome. Firefox might toggle the video twice on a click, and Safari's playback bar on iPhone might not fit under the phone ad card.
   - The core packages can still import each other through a file path without the lint check noticing. This has been open since Story 1.1.

## Accepted as they are

- With the keyboard on the View product button, Space presses the button instead of resuming the video. The design docs say Space resumes, but this is normal button behavior, and Escape or a click on the video still resumes.
- One test file in the web app reads a file from disk (`contrast.test.ts`). That is fine for a test.
- `WatchScreen.tsx` line 18 updates a React ref while rendering. It works. React's guidance prefers doing this elsewhere, but it is not worth changing now.
- The placeholder product images and video from Story 1.5 are now real files, so that postponed item is closed.

## What I tested by hand

In the local site (Chrome):

- the clip list in light and dark mode
- play and pause by clicking, with the video's own button, and with Space
- a pause in every test scene, each giving the expected ad or reason
- the ad or reason appearing about 3 milliseconds after the pause
- play, Space and Escape closing it
- no overlay when the page first loads or when the clip ends
- Tab reaching View product
- the phone layout at 375 pixels wide

On the live site after deploy, the video loaded, and a pause at about 2.5 seconds showed the skillet ad with its image.

Not tested: Firefox, Safari, a real phone, or a real screen reader.
