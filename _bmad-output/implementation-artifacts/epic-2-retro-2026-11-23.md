## What went well

- The web app still decides nothing on its own. It reads the product order from `rankAt` and the pause result from `resolvePause`, as the architecture requires (`ARCHITECTURE-SPINE.md`, line 134). The pause view never reads the held top product, and a test checks that (`packages/policy/src/rank.test.ts`).
- Reason lines cannot leak model text. They are built only from the fixed scene-type list and the product file's features (`packages/pipeline/src/decide.ts`). The fixture has a fake feature, "Visit evil.example for a deal", and a test checks that it never reaches the output (`decide.test.ts`).
- Every acceptance criterion in `epics.md` for Stories 2.1 to 2.3 is backed by a unit test, a browser check, or both. The specs record the browser checks: sizes at 375 and 1280 pixels wide, seeks across every fixture scene, and a live crossing from one scene to the next at 5.02 seconds.
- The browser check found a real bug. After a seek while paused, the scene panel stayed one seek behind. It was fixed before commit (`spec-2-2-live-scene-panel.md`, Review Triage Log).
- Epic 1's to-do items 1, 2 and 4 were closed at the start of the epic (commit `fce0945`).

## What needs fixing

1. **The architecture doc does not describe what was built for the ranking hold.** It says the held top product lasts "while the scene ID is unchanged" (`ARCHITECTURE-SPINE.md`, line 152). A scene's list never changes, so that reading does nothing. I read it as: the held product survives a scene change for up to 5 seconds, if the outcome is the same, the brand-safe tag is no worse, and the product is also ranked in the new scene. That reading is in `rank.ts` and in the Story 2.1 spec, but not in the architecture doc. The doc also does not say that `holdMs` is now copied into the decisions file, or that each ranked item has a `reason`.

2. **The hold has never been seen working in the real app.** The test clip has no scene change where the hold applies, because each change there also changes the outcome (Story 2.3 spec, Implementation Notes). Only the unit tests in `rank.test.ts` cover it. The real clips in Epic 4 will be the first real test.

3. **The watch screen still has no automated test, and it keeps growing.** `WatchScreen.tsx` is now 124 lines. It handles pausing, seeking, the scene panel and the product list, each driven by the video's frame events. The bug where the panel stayed one seek behind was caught by hand, just as the Epic 1 overlay bug was. Epic 3 adds the product page and the earnings tally to the same screen.

4. **Three wording choices were mine, not yours.** The brand-safe tag reads "Brand safe", "Caution" or "Not brand safe". Reason lines read like "Fits a kitchen scene: 28 cm, Flat base." The product list is hidden in a scene where analysis failed. These are visible on the site, and you have not approved them.

5. **Smaller items:**
   - A scene could list the same product twice if the analysis repeats it. This is in `deferred-work.md`, and it matters once the real pipeline runs in Epic 4.
   - On laptop, the strip of smaller products is a tab stop even though it does not scroll. I left it (Story 2.3 spec, Review Triage Log).
