# Epic 3 retrospective

Epic 3 passed, with a few open items. All three stories are finished and merged into main on this machine:

## What this review covered

## What went well

- The web app does not work out any money itself. When you pause on an ad, the price and the 70/30 split come from that scene in the decisions file (`apps/web/src/pause-view.ts`). The earnings list only formats values marked as simulated (`apps/web/src/earnings.ts`). The architecture requires this (AD-8).
- The simulated click stays in the browser. It is held in the page's memory (`apps/web/src/App.tsx`) and never sent or saved (AD-23).
- Going to the product page and back keeps your exact paused frame and the same ad card. While the product page is open, the watch screen stays loaded but hidden, so nothing is rebuilt (`App.tsx`). In the browser check, both the Back link and the browser's Back button returned to 2.0003 seconds with the same card (Story 3.1 spec, Implementation Notes).
- Review caught two real bugs before they were committed. A reloaded product page said "Simulated click recorded." when nobody had clicked (Story 3.1 spec, Review Triage Log). The links on the attribution page would have cleared your earnings when you came back (Story 3.3 spec, Review Triage Log). Both are fixed.
- I caught a wrong number in a spec before writing any code. The Story 3.2 test table assumed the test ad costs 96 cents. The decisions file says 108, so I fixed the table first (Story 3.2 spec, Implementation Notes).
- Epic 2 to-do items 1 to 3 were closed at the start of this epic (commit `309f1a0`).

## What needs fixing

1. The earnings line does not match the design docs. The docs show "Simulated earnings: 2 ads shown, 1 held back (0)" (`EXPERIENCE.md`, lines 43 and 115; `epics.md`, lines 114 and 441). The site shows "Simulated earnings: 2 ads shown ($2.16), 1 held back ($0.00)". The docs did not say what the "(0)" counts or which currency to use. I chose to show what the shown ads earned, put the held-back zero next to its count, and use US dollars (Story 3.2 spec, Boundaries). I also chose "Demo QR, not a real link" on the ad card, "Back to the clip" on the product page, and "Details" or "Hide" on the earnings line. You have not approved any of this wording, and the docs still show the old example.

2. The watch screen still has no automated test, and it grew again. The Epic 2 retrospective flagged this (item 3), and you chose to wait for Story 5.5. In this epic `WatchScreen.tsx` went from 124 to 143 lines, and `App.tsx` now holds the list of pauses and picks which screen to show. The rules that matter most only show up in a real browser: one row for each real pause, no row when you move the video while paused, no row for a trip to the product page, and the click saved on the latest pause. I checked these by hand in this epic. No test checks them.

3. A click can be saved on the wrong pause. Say you pause on a scene with no ad, then move the video, still paused, to a scene with an ad. The ad card appears, but the list keeps the row for the first scene. If you then select View product, the click is saved on that no-ad row (`apps/web/src/session.ts`, `withClick`). I reproduced this on main: a pause at 12.5 seconds ("nothing fits"), a move to 31 seconds, then View product. The click is not shown anywhere yet, so nobody sees the mistake today. It only matters once something shows or counts clicks.

4. Smaller items:
   - Some style strings are copied from file to file. The Back link style is in 5 files and the small uppercase label style is in 4 (`apps/web/src/*.tsx`). Changing either look means editing every copy.
   - The Story 3.3 spec says the attribution page has "two outside links". It has three: ABO, the paper and the licence (`spec-3-3-attribution-page.md`, line 17).
   - The attribution page says ABO is licensed under CC BY 4.0, but nobody has opened the licence file yet. This was already on the list to settle before the real catalog arrives in Epic 4.

## Accepted as they are
