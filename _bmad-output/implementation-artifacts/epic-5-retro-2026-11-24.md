# Epic 5 retrospective

## In short

Epic 5 gives Pausall a way to check its own work. A new command, `pnpm eval`, pauses every clip at every tenth of a second and asks the same code the app uses whether it would show an ad there. It then compares each answer with labels a person wrote by hand. If an ad ever lands on a moment the labels call unsafe, the check fails, and so does GitHub's build.

Everything was built and tested on the small hand-made test clip from Epic 1, because the AI-generated sample clips have not arrived yet. The tools are ready. The real measurement waits for those clips and for Sam's labels.

Nothing has been pushed. `main` has one new commit (70768ad) on top of the Epic 4 work, and it stays local until the AI clips are in, for the same reason as before: the public clip list would be empty.

## What we built

- A label file per clip in `data/labels/`. Each entry covers a stretch of time and says whether it is safe, which sensitive topics appear (violence, death, and so on), and whether the product the app shows there really fits. Sam had not said how labels should look, so Claude picked this shape. It can change when real labeling starts.
- `pnpm eval`. It checks every 0.1 seconds of each clip, plus the moments just before, at and after every scene change. It matches results to labels by time, never by scene number, so a change in how scenes are cut cannot hide a mistake.
- A safety check with no easy way to pass. It fails when an ad lands on unsafe time, and also when a labeled stretch was never checked, when there is less than 5 seconds of unsafe material in total, or when any sensitive topic has no labeled example. "Zero bad ads out of zero checked" counts as a failure.
- A report in `docs/eval/report.md`: how often the app agrees with the labels about fit (the target is 80 percent), how often it holds back an ad, how often the product list reshuffles while you watch, cost per minute of video, and a table of every mistake with its clip and time.
- `pnpm eval --compare-judges`. It runs only on Sam's computer and asks Qwen the same questions Jev answered, then reports how often each judge matches the labels and what each costs. It never changes the saved analysis.
- A browser test. It builds the real site, opens it in Chrome, pauses the test clip at 7 moments, and checks three things: the pause screen shows up within half a second, it says what the rules say it should, and the page fetches nothing new after it has loaded.
- Each analysis run now saves its cost per stage. Epic 4 only printed it on screen.

## What the test clip showed

- No ads on unsafe time: 0 out of 102 checked moments.
- Agreement on fit: 94.5 percent. This only proves the counting works. The test clip's answers and labels were both written by hand.
- The report lists three "held back when it could have shown an ad" cases. Two come from the 1-second look-back rule: just after a risky scene ends, the app still plays it safe. The third is the scene that is deliberately marked "analysis unavailable". All three are the rules doing what they were designed to do.

## Problems we found and fixed

The browser test failed the first time, and both failures were real problems in the app:

- One font weight loaded only when the first ad card appeared. That meant a network request at the moment of pausing, which the architecture rules out. The app now loads every font when it starts.
- A product photo was fetched a second time even though the app had preloaded it. The preloaded copy was being thrown away. The app now keeps it.

After both fixes the test passes: every pause screen appeared well within half a second, and the only request after loading was the video itself streaming.

## Things that are still not perfect

- The browser test allows the video to keep downloading in pieces after the page loads. That is the video playing, not an API call, but it is an exception to "no network".
- GitHub's build has not run the browser test yet. It relies on the Chrome that GitHub's Linux machines come with. We find out on the next push.
- The test clip will stay in the eval alongside the real clips unless we decide otherwise, and it would mix fake numbers into the real ones.
- The cost lines in both reports say "not recorded" until the clips are analyzed again with the new cost saving.
- The test clip has no unsafe moment shorter than 2 seconds, so we cannot tell yet whether checking one frame per second misses quick events.
- The browser test does not yet cover the pause log rows from Epic 3 (open item 12).

## What we learned

- The browser test earned its place on its first run. Both problems it found were invisible in normal use on a fast connection.
- Writing the "cannot pass by checking nothing" rules into code early pays off. It is easy to see 0 failures and stop looking.
