- (constraint) Inherited from PRD/policy: pause view <500 ms from stored lookup; playback never waits on analysis; unknown/low-confidence/failed analysis means no ad; classify safety from scene description not raw transcript; second agreeing signal required; SceneJudge interface swappable (Jev vs Qwen LLM judge, LLM is fallback); Qwen single provider; uploads behind flag, off at first release, nothing stored; cost under 10 USD/month; all ads/revenue labeled simulated; ABO catalog slice ~20k products, CC BY 4.0 attribution; IAB taxonomy file not committed; 4 sample clips, up to 2 min, chunked analysis first 20 s first; scene profile = description, type (primary+optional secondary), sentiment -1..1 with mood, safety verdict+reasons+confidence.
- (decision) AD paradigm: Precompute + seam (option C). Offline pipeline library (frames -> VLM description -> SceneJudge -> retrieval/ranking -> taglines) run by CLI emits one static JSON bundle per sample clip; web app is static and the pause decision is a pure function in the browser over the bundle. Pipeline is one library behind SceneJudge interface so a server host can be added later behind the upload flag. Binds: pipeline vs web boundary, bundle as the only contract. Prevents: runtime model calls on the playback/pause path, two divergent analysis implementations. Consequences: FR-22 becomes ordering property of bundle (first 20 s chunk first); 'Analyzing' and 'analysis unavailable' UX states only for uploads or simulated; FR-8 hysteresis runs client-side over precomputed scores.
- (question) Reconcile with PRD: FR-22 and UX state patterns (first chunk not analyzed, pause before analysis reaches scene) need a PRD/UX note that they apply to uploads only for samples. Raise at Finalize.
- (decision) AD stack: TypeScript pnpm workspace (packages/bundle-schema, packages/pipeline CLI, apps/web). Web = Vite + React + TS SPA, Tailwind v4 with Soft Calm tokens as CSS variables, native video element, NO component library (Radix only if a single piece is later needed). Bundle schema is the one shared contract between pipeline and web. Binds: language, package boundaries, UI approach. Prevents: schema drift across languages, UI lib churn. Versions NOT verified: Vite major (7 vs 8 conflicting), React, Tailwind v4.x, Astro/Next rejected; pin with npm view at scaffold. Qwen models seen: qwen3-vl-flash, qwen3-vl-plus; prices/regions unverified.
- (decision) AD bundle/decision: fully precomputed bundle. Per scene: scene profile, top-10 products with score/reason/tagline, both judge verdicts, campaign flag, analysis status. Browser runs only pure decidePause(sceneId) plus FR-8 hysteresis (5 s). Decision logic lives in one package packages/policy (pure function, thresholds passed in from one config file); pipeline evaluation and web both import it so the zero-unsafe-ads guardrail is tested on shipped code. Threshold change = re-run decide step, no model calls. Binds: policy package ownership, bundle contents. Prevents: decision logic duplicated in pipeline and browser; model/catalog/embeddings in browser.

- (decision) AD pipeline: stages ingest (ffmpeg 1fps ~512px, audio only if dialogue) -> segment by frame change, 3-4 frames/scene -> describe (Qwen VLM; dialogue summarized neutrally inside description step, no raw transcript to any judge) -> judge -> retrieve (~200 candidates via embeddings from non-committed catalog index; only products used in bundles copied in with small images + attribution) -> fit (context = current + previous 3 descriptions) -> generate reasons/taglines only for scenes passing policy safety rules via packages/policy, tagline failing product-data check falls back to product name. Two artifacts: analysis/<clip>.json (model outputs + token/cost metadata, committed) and decisions/<clip>.json (derived by packages/policy from analysis + thresholds file + campaigns file, regenerated, no model calls). Web reads decisions + clip manifest only, never analysis. eval command in pipeline compares judges to human labels and checks guardrail with same policy code; outputs to docs/eval/. Pipeline design adopted by Sam implicitly (no objection; amended by judge decision).

QwenJudge is fallback for type/sentiment/fit if Jev errors. Jev-vs-LLM comparison for evaluation is a separate offline eval run, shipped path never depends on it. Binds: which questions run on which judge. Prevents: double-running fit scoring, shipped path coupled to comparison.
